Health on Point — Pharmacy Platform

A pharmacy e-commerce platform with prescriptions, telehealth consultations and a full admin panel.

Overview

A pharmacy platform that is three products sharing one codebase: a storefront selling across 20+ product categories, a healthcare layer covering 7+ medical services with prescription management and online video consultations, and an admin panel the pharmacy runs its day-to-day operations from.

The complication is that a pharmacy is not a normal store. A prescription item cannot be added to a basket and checked out like a bottle of shampoo — it has to be uploaded, reviewed and approved before the order can complete, which means the cart, the checkout and the order state machine all have to model an item that is pending someone's judgement.

My Role

Lead Frontend Developer. I led frontend development for the platform and the admin panel, integrated authentication, cart, payments and the real-time API sync between them, and worked with the FastAPI backend team to settle the data flow and payment handling. I also took the build from Figma through to production deployment with Docker and CI/CD, and mentored two junior frontend developers on the same codebase.

Key Features

What the system actually does.

20+ product categories
A full pharmacy catalogue with browsing, search and filtering across every category the pharmacy stocks.
Prescription management
Customers upload a prescription against an order; the item stays pending until it is reviewed, so a restricted product can never checkout unapproved.
7+ medical services
Bookable healthcare services sitting alongside the storefront rather than on a separate site.
Online video consultations
Patient-to-practitioner video appointments implemented with the Zoom SDK, booked and joined from inside the platform.
Cart, checkout and payments
Authentication, cart management and card payment through Peach Payment, with order state kept in sync with the backend in real time.
Admin panel
Sales reports, inventory, staff and service management, and promotional email campaigns — built with React and Redux Toolkit.
Containerised deployment
Docker images built and shipped through GitHub Actions CI/CD to the production server.

Challenges & Solutions

The problems that shaped the build, and what I did about them.

A prescription item breaks the normal cart model

Standard e-commerce assumes any item in the basket can be paid for immediately. A prescription item cannot — it needs upload, review and approval first, and mixing both kinds in one order means checkout has to handle a partially-blocked basket.

Solution: Modelled approval as part of the line item's own state rather than the order's, so the cart can hold approved and pending items together and checkout knows precisely which portion it is allowed to take payment for.

Three surfaces, one source of truth

Storefront, consultations and admin panel all read and write the same inventory and order data. Stale state in any one of them shows a customer a product the pharmacy has already sold.

Solution: Standardised every server interaction on RTK Query with tag-based invalidation, so a write in the admin panel invalidates the reads that depend on it instead of each screen managing its own refresh.

Payment correctness is a two-team problem

The payment flow spans the React frontend and a FastAPI backend, and the failure modes that matter — a charge that succeeds while the order fails to record — sit exactly on the boundary between them.

Solution: Worked directly with the backend team to agree the contract and the failure handling at that boundary, rather than each side defending against the other's edge cases independently.

Results

What shipped, and what changed because of it.

  • Shipped a pharmacy storefront spanning 20+ product categories and 7+ medical services on a single platform.
  • Prescription orders and video consultations run inside the same system the pharmacy already sells from, rather than through separate tools.
  • The pharmacy runs sales reporting, inventory, staff and campaigns from one admin panel.
  • Deployment moved to Docker images shipped by GitHub Actions, so releases are repeatable rather than hand-copied.
