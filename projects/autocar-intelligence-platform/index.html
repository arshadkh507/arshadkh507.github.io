AutoCar Intelligence Platform

Operational intelligence giving multi-shop auto repair owners one source of truth.

Role
Frontend / Full Stack Developer
Timeline
Nov 2025 — Jan 2026
Category
Full Stack
Case study
techemulsion.com

Overview

A centralised operational intelligence platform for owners running several auto repair shops. Before it, answering "how did we do this month?" meant logging into each shop's system separately and reconciling the numbers by hand.

My Role

I built the aggregation layer and the analytics surfaces on top of it, including the hybrid data pipeline needed to reach metrics the vendor API does not expose.

Key Features

What the system actually does.

Multi-shop data aggregation
Normalises inconsistent fields across shops into one comparable dataset.
Historical snapshots
Month-over-month and year-over-year comparison from point-in-time snapshots.
Auditable calculations
Sales and profit figures computed deterministically, so an owner can trace any number back to its inputs.
Aging work-in-progress tracking
Flags high-dollar repair orders sitting without a deposit.
Hybrid data pipeline
Combines the Tekmetric API with a Chrome extension for metrics the API does not expose.

Tech Stack

What it's built with.

React Supabase PostgreSQL Tekmetric API Chrome Extension

Challenges & Solutions

The problems that shaped the build, and what I did about them.

Challenge

Each shop entered the same concepts differently, so naively combining their data produced totals that did not match any individual shop's own reporting.

Solution: Built a normalisation layer that maps each shop's field variants onto one canonical schema before any aggregation happens.

Challenge

Several metrics owners most wanted were visible in the vendor's own interface but absent from its API.

Solution: Paired the API with a Chrome extension that captures the missing metrics from the authenticated session, feeding both into the same pipeline.

Challenge

Owners will not trust a dashboard whose profit figure they cannot reproduce.

Solution: Made the sales and profit calculations deterministic and inspectable rather than opaque aggregates, so every figure can be audited.

Results

What shipped, and what changed because of it.

  • Multi-shop performance readable from one dashboard instead of separate per-shop logins.
  • Month-over-month and year-over-year comparison available from historical snapshots.
  • High-dollar repair orders without deposits surfaced automatically rather than found by chance.
