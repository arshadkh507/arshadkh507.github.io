Overview

A content automation system built for a marketing content agency that needed to publish articles capable of ranking, at a volume no writer could sustain by hand.

Rather than one model asked to do everything, the work is split across specialised agents — research, keyword analysis, content generation — running on the Hermes agent runtime, with Multica providing the orchestration and the observability over what each agent actually did. Live SEO data reaches the agents through the DataForSEO MCP server, generated articles and workflow outputs persist in Supabase, and Slack is where a human starts a run and approves what comes out of it.

My Role

I built the orchestration layer: how the agents are specialised, how work passes between them on the Hermes runtime, what Multica surfaces about a run while it is happening, where results are durably stored, and where a human is required to approve before anything reaches publication.

Key Features

What the system actually does.

Hermes agent runtime
Each specialised agent runs on Hermes rather than as an ad hoc script, so they share one execution model instead of one integration per agent.
Multica orchestration & observability
Multica coordinates the handoffs and makes a run legible while it is happening — which agent ran, on what input, and what it returned.
SEO research and keyword analysis
Live keyword and competitive data gathered as input to drafting.
DataForSEO MCP integration
SEO data reaches the agents through MCP rather than bespoke glue per agent.
Durable outputs on Supabase
Intermediate and final results persist, so a long run is inspectable and resumable.
Human approval workflow
A required review gate before anything is treated as publishable.
Slack triggering
Runs kick off from Slack, where the team already works.
Specialised agent roles
Research, keyword analysis and content generation are separate agents with narrow briefs, not one prompt asked to do all three.

Challenges & Solutions

The problems that shaped the build, and what I did about them.

One model doing three jobs does all three badly

A single model asked to research, plan and write at once produces shallow work on all three.

Solution: Split the work across specialised agents with narrow responsibilities and orchestrated the handoffs between them.

Unattended publishing is how bad content ships

Generation at volume with no gate is exactly how off-brand or factually wrong content reaches a client’s live site.

Solution: Made human approval a required stage rather than an optional review, so automation ends at the draft and a person decides what ships.

A long multi-agent run is opaque while it is running

Multi-agent runs take a long time, and losing every intermediate result to one failed step makes them impractical. Worse, with no view into the run there is no way to tell a slow agent from a stuck one.

Solution: Persisted agent outputs durably in Supabase so runs are inspectable during execution and recoverable after a failure, and used Multica’s observability so progress is visible per agent rather than inferred from the final output.

Results

What shipped, and what changed because of it.

  • Keyword research through to draft article runs as one automated pipeline.
  • Content generation triggers from Slack without anyone opening the tooling.
  • Nothing publishes without passing an explicit human approval gate.
